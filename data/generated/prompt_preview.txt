## 业务错误码
# mini-mall 业务错误码约定

接口测试的核心不是“通不通”，而是“失败时是否符合约定”。本表同时作为 AI 生成用例的输入上下文。

## 信封格式

```json
{ "code": 0, "message": "ok", "data": {} }
```

- `code == 0` 表示业务成功；
- `code != 0` 表示业务失败，`message` 为可直接展示给用户的原因；
- HTTP 状态码只表达传输/鉴权/权限/限流语义，**业务失败默认仍是 HTTP 200**。

## 错误码

| code | HTTP | 含义 | 典型触发 |
| --- | --- | --- | --- |
| 0 | 200 | 成功 | — |
| 1001 | 200 | 用户名或密码错误 | 密码错误、用户不存在 |
| 1002 | 200 | 商品已下架 | 对 `onSale=false` 商品下单/加购 |
| 1100 | 400 | page 非法 | `page=0` |
| 1101 | 400 | size 超范围 | `size=51` |
| 2002 | 200 | 库存不足 | 数量大于 `stock` |
| 3001 | 409 | 订单状态不允许支付 | 重复支付、支付已取消订单 |
| 3002 | 409 | 订单状态不允许取消 | 取消已支付订单 |
| 4001 | 401 | 未登录/缺少 token | 无 `Authorization` 头 |
| 4002 | 401 | token 无效或过期 | 伪造签名、过期 |
| 4003 | 403 | 无权限 | 越权查看/操作他人订单、普通用户访问管理端 |
| 4004 | 404 | 商品不存在 | `/api/products/999` |
| 4005 | 404 | 订单不存在 | `/api/orders/99999` |
| 4009 | 403 | 测试模式未开启 | 调用 `/api/_test/reset` |
| 4029 | 429 | 登录失败次数过多 | 同一账号 60 秒内失败 5 次 |
| — | 422 | 参数结构与类型校验失败 | 缺字段、`quantity=0`、类型错误（由 FastAPI 返回 `detail`） |

## 对测试的要求

1. 每个非 0 错误码至少有一条用例，且同时断言 HTTP 状态码与 `code`；
2. 不允许只断言 `status_code == 200`；
3. 401 与 403 必须区分：未登录是 401，登录了但没权限是 403；
4. 422 由框架抛出，响应体是 `{"detail": [...]}`，不能套用上面的信封断言。

## OpenAPI 里没有、必须额外喂给模型的信息

`docs/openapi.json` 只描述「结构」，不描述「业务语义」，抽取出的 `data/generated/operations.yaml` 存在三处缺口：

| 缺口 | 现象 | 对生成用例的影响 | 兜底 |
| --- | --- | --- | --- |
| 业务错误码缺失 | spec 里只有 200 / 422 两个响应，1001/2002/3001 等业务码完全没有定义 | 模型只能臆造 code，或退化成只断言 200 | 本文件作为独立上下文拼进 prompt；脚本丢弃只断言状态码的草稿 |
| 错误响应没有 schema | 除 422 外，错误分支要么没有 `responses` 条目，要么是 `additionalProperties: true` | 模型无法断言错误响应结构 | 用例统一 `schema: error`（envelope 结构），由 `config/schemas/error.json` 校验 |
| 成功响应过于笼统 | 几乎所有 200 都是 `type: object, additionalProperties: true`，字段名与类型不可见；参数 schema 为空对象、无 `example` | 模型不知道 `data.items[].price` 这类真实字段，容易编造 `productName` | prompt 里只允许引用接口定义中出现的字段；字段级错误靠人工审核拦截 |


## 输出 JSON 结构
{"cases": [{
  "id": "ai_<snake_case>",
  "title": "中文用例标题",
  "method": "GET|POST|DELETE",
  "path": "只能取自接口定义",
  "auth": "anonymous|user|other|admin|bad_token",
  "params": {},
  "json": {},
  "expected": {"status": 200, "code": 0, "schema": "product_list|product|login|profile|order|error", "jsonpath": {}, "not_null": []},
  "needs_review": true,
  "review_reason": "为什么需要人工确认（无则空字符串）"
}]}

## 约束
- 业务失败是 HTTP 200 + code!=0，鉴权缺失 401、越权 403、状态机冲突 409、限流 429、参数校验 422；
- schema 只能从 error|login|order|product|product_list|profile 中选择；无法判断结构的用例把 schema 设为 null 并说明原因；
- 无法自证（需要预置已支付订单、需要并发、需要过期 token）的用例必须 needs_review=true。
